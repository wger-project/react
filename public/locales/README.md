i18n README
===========

To extract new strings `npm run i18n`, actual translation occurs in weblate:
<https://hosted.weblate.org/projects/wger/frontend/>

More info: <https://react.i18next.com/>

Plural forms
------------

The frontend uses i18next JSON v4 plural keys. Call the base key with a numeric
`count`, for example `t('measurements.chartRangeMonths', { count: 3 })`.
English uses `_one` and `_other`; target languages can require additional
categories such as `_two`, `_few`, or `_many`. Keep `{{count}}` available in
translations whose plural category applies to several numbers.

For Weblate to group these variants and offer each language's plural forms,
the intended frontend component configuration is:

| Setting | Value |
| --- | --- |
| File format | i18next JSON file v4 (`i18nextv4`) |
| File mask | `public/locales/*/translation.json` |
| Monolingual base language file | `public/locales/en/translation.json` |

Weblate's generic JSON formats (`json` and `json-nested`) do not support plural
forms. See the [Weblate i18next documentation](https://docs.weblate.org/en/latest/formats/i18next.html)
and [i18next plural documentation](https://www.i18next.com/translation-function/plurals).

Before changing an existing Weblate component, back up pending translation work
and verify the format change on a test component. After rescanning, check that
existing translations and ordinary keys are preserved and that required plural
forms survive a translation export and another source extraction. Compare every
existing plural key as well as ordinary keys: parsers can select different
categories for a target language, so preserve and review translations under old
suffixes before allowing an export to replace them. Do not automatically rename
a translated variant into a different grammatical category. Translators
still need to supply the missing forms; changing the format does not translate
them automatically. The component's format is a Weblate administration setting,
so updating this README alone does not change the running translation service.

An offline round-trip of the catalogues at
[`aa35c0c3`](https://github.com/wger-project/react/commit/aa35c0c36f70d345872d17944a4d1e079fa037cd)
with Translate Toolkit 3.20.2
illustrates why this check matters: its default Ukrainian categories exclude
`other`, and its Slovak categories exclude `many`. Exporting through that parser
omits seven existing Ukrainian `_other` values and two Slovak `_many` values.
This is a parser-level check, not a test of Weblate's migration or translation
memory. Verify the actual Weblate version and merge behavior on a test component
and preserve those values for translator review before enabling writes.

Please note that the contents of i18n.tsx contains the values of the exercise categories, equipment, etc. and is
autogenerated on the wger repo by the extract-i18n.py script (python manage.py extract-i18n).
